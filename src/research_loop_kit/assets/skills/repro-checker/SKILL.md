# 再現性の確認

## 適用範囲

plan / implementation_review / review。分野に依存しないAgent手順として利用する。
実行前に[入出力と判断例](references/contract.md)を読み、現在の作業票の契約を優先する。

## 手順

1. 再現対象のコード版、入力ハッシュ、設定、環境、seed、記録値を確認する。不足がある場合は再現未確認と記す。
2. 同一コード・入力・設定で再実行する検査と、現行コードへの回帰検査を区別する。差があってもどちらを調べたか曖昧にしない。
3. 軽量な決定論的関数はimplementation_review.testsで固定入力の期待値と比較する。期待値は仕様・手計算・独立記録から決める。
4. 全実験の再実行が必要なら新しい候補・計画として提案する。レビュー中に予算外の実験を走らせたり過去ログを書き換えたりしない。
5. 許容差は単位、浮動小数点、測定分解能から事前に決める。確率的処理にdiff=0を強制しない。失敗や未実行を一致扱いにしない。

## 制約

特定のbest_configや画像評価器への依存を除いた手順。過去実験を一括再実行する専用CLIや環境の自動復元はない。
研究データ、実験番号、非公開リポジトリ、元研究固有の定数やコードに依存しない。
未実行・対象なし・必要入力欠落をPASSにしない。状態DBと既存成果物を直接編集しない。
