# 比較基準と測定値の管理

## 適用範囲

plan / review。分野に依存しないAgent手順として利用する。
実行前に[入出力と判断例](references/contract.md)を読み、現在の作業票の契約を優先する。

## 手順

1. 基準の名称、指標定義・単位・方向、入力ハッシュ、条件、コード版、環境、seedと実験IDを確認する。出典なしの値を公式値と呼ばない。
2. 仕事票のhistoryと実測結果から、条件が同じ測定だけを抽出する。違うデータ・環境・予算の値を混ぜない。
3. 失敗・partial・未検証の測定を成功標本から分け、件数と理由をlimitationsに記す。既存の結果やDBを上書きしない。
4. 統計を再計算するなら各seedの原値を使い、欠損・重複を確認する。集計値しかない過去報告はseed追加の統合対象にしない。
5. 既存基準の変更理由と比較可能性をreviewのinterpretationへ、新しい基準の提案をnext_questionsへ記す。新規データは別の実験として残す。

## 制約

専用の追記型registry CLIは移植しない。履歴と報告に比較基準を整理するAgent手順であり、外部ベンチマークの公認を保証しない。
研究データ、実験番号、非公開リポジトリ、元研究固有の定数やコードに依存しない。
未実行・対象なし・必要入力欠落をPASSにしない。状態DBと既存成果物を直接編集しない。
