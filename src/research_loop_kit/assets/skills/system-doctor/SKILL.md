# 研究システムの診断

## 適用範囲

review / 手動診断。分野に依存しないAgent手順として利用する。
実行前に[入出力と判断例](references/contract.md)を読み、現在の作業票の契約を優先する。

## 手順

1. 作業票の範囲で計画、コード、入力記録、ログ、測定値、履歴を読み、期待する資源が存在するか照合する。
2. 所見は事実・証拠のパス・影響・推奨対応に分ける。古いログや言及0件だけで現在の状態や機能不在を断定しない。
3. 失敗・欠損・契約違反はinvalid、結論が判断できない場合はinconclusiveとし、各実験のlimitationsへ診断結果を返す。
4. 実行中のジョブを止めたり、DBを編集したり、許容例外を追加したりしない。復旧は正規の入口と利用者の依頼範囲で別途行う。
5. 提供されていない資源の診断は未実施と明示する。診断スクリプトのexit 0だけで健全と判断せず、確認対象と所見を示す。

## 制約

元システムの総合診断スクリプトは同梱しない。診断観点をAgentレビューへ接続し、自動修復や全環境診断は行わない。
研究データ、実験番号、非公開リポジトリ、元研究固有の定数やコードに依存しない。
未実行・対象なし・必要入力欠落をPASSにしない。状態DBと既存成果物を直接編集しない。
