# 動的な配線確認

## 適用範囲

implement / implementation_review。分野に依存しないAgent手順として利用する。
実行前に[入出力と判断例](references/contract.md)を読み、現在の作業票の契約を優先する。

## 手順

1. 計画の変更因子、入口、共通API、期待する観測を対応表にする。静的な参照の存在だけで実行済みとしない。
2. implementation_reviewのtestsに、experiment.pyの実入口を小さな条件・検証用seedで呼ぶunittestを返す。共通コードは作業票の固定版を使用する。
3. 呼出し回数、処理対象、または中間結果で到達を確認する。無効条件を対照にしてテストが実際に失敗することも確認する。
4. 設定の2点比較は計画上効果が期待される条件で行う。最終指標が同じだけで未配線と断定しない。丸め、飽和、確率変動、効果ゼロの仮説を区別する。
5. 到達しない・契約違反はrejected。期待効果が未定義なら計画へ差し戻す。対象0件をpassedにしない。

## 制約

元研究の評価器・探索空間・固定閾値は同梱しない。動的検査はAgentが生成し、既存ランタイムが実行する。
研究データ、実験番号、非公開リポジトリ、元研究固有の定数やコードに依存しない。
未実行・対象なし・必要入力欠落をPASSにしない。状態DBと既存成果物を直接編集しない。
