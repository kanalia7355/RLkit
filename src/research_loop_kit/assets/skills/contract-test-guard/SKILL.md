# 実境界の契約テスト

## 適用範囲

implement / implementation_review。分野に依存しないAgent手順として利用する。
実行前に[入出力と判断例](references/contract.md)を読み、現在の作業票の契約を優先する。

## 手順

1. 変更した送信側・受信側、入出力の型、必須項目、単位、エラー処理を列挙する。
2. implementation_review.testsで送信側の実出力を受信側へそのまま渡す。両側を独立に手製モックへ置き換えた試験だけで境界を保証しない。
3. 正常経路に加え、必須項目欠落、型違い、非有限数値、seed違いなど関連する拒否条件を検査する。
4. 呼出し未到達、テスト0件、例外を捕まえたままassertなしを合格にしない。テストの失敗をランタイムへ返し、実験開始前に直す。
5. 不整合はimplementation_reviewでrejectedとし、具体的な修正箇所をsummaryへ記す。状態DBや別ジョブを直接修正しない。

## 制約

元の通信ブリッジ用pairs.jsonや外部送信は移植しない。実験の固定コードに対する既存のunittest実行へ接続する。
研究データ、実験番号、非公開リポジトリ、元研究固有の定数やコードに依存しない。
未実行・対象なし・必要入力欠落をPASSにしない。状態DBと既存成果物を直接編集しない。
