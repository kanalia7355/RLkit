# 計測条件と負荷の管理

## 適用範囲

plan / review。分野に依存しないAgent手順として利用する。
実行前に[入出力と判断例](references/contract.md)を読み、現在の作業票の契約を優先する。

## 手順

1. 測定区間、単位、ウォームアップ、反復回数、両条件の実行順、キャッシュの扱いをmethodで固定する。
2. OS・Python・パッケージ版に加え、必要ならCPU/GPU、電源設定、スレッド数、同時実行数を記録する。取得できない値は未取得とする。
3. 同時実行や他プロセスが比較に干渉するなら並列数を制限する計画を提案する。既存の利用者プロセスを終了しない。
4. 探索速度と介入・前処理・入出力を含む総時間を分ける。対照と介入に同じ比較予算を適用する。
5. レビューでは固定条件と実測条件を照合し、負荷が未測定なら環境依存というlimitationsを残す。負荷を観測していないのに制御済みと記さない。

## 制約

OSの負荷制御やハードウェア監視は自動実装しない。時間指標の採用可否を判断する計画・レビュー手順。
研究データ、実験番号、非公開リポジトリ、元研究固有の定数やコードに依存しない。
未実行・対象なし・必要入力欠落をPASSにしない。状態DBと既存成果物を直接編集しない。
