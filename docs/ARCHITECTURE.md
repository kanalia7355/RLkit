# 元システムを継承した汎用構成

## 目的と二段構造

元のlab_exはGA・画像処理の実験自動化システムで、研究方針を扱う上位ループと実験を実行する下位ループを持っていた。
RLkitは計画、実験、検証、分析、報告、次の提案という目的を継承する。
実行に必要な原コード・STATE・Git同期・通知接続は持ち込まず、独立ランタイムとして再実装している。
元の全構成との互換や、原システムの未解決なproduction状態の解消を保証しない。

| 元の要素 | 引き継ぐ目的 | 現行構成・分野固有部分 |
|---|---|---|
| 世代・個体の探索と評価 | 結果から次の探索を決める | 研究cycle、ideas、plan。GA探索空間はテンプレート側 |
| 画像入力・前処理 | 入力条件を固定する | data_files、固定コピー、共通src。画像固有処理は研究実装側 |
| fitness・専用指標 | 成否を事前に決める | metric、direction、min_effect。指標の妥当性はレビュー対象 |
| 介入・placebo | 効果と費用を切り分ける | baseline/treatment、comparison_policy。placeboを全研究へ強制しない |
| 世代停止・収束 | 有限の試行と停止理由を残す | stop_policy、条件別記録、任意の研究時間予算 |
| 世代履歴・KB・改善案 | 知見を次の実験へ反映する | history、Markdown報告、ideas、承認付きスキル育成 |

## 制御の流れ

初回の聞き取り → 追加質問 → 候補 → 方針 → 実装 → 実行前レビュー → 実験 → 分析・レビュー → 報告 → 次の候補。
review_each_cycleは方針ごとに確認し、boundedは初回承認の設定・研究プロファイルの範囲で次へ進む。
未解決事項、予算、失敗、停止指示を保持する。自然言語による範囲外変更の判断にはAgentの確認も必要。

数値実験はランタイムがPythonプロセスを起動し、Agentの自己申告だけで完了にしない。
現在の実行口はseedを対応付けた2条件の数値比較。図表生成・分野別テンプレート・他の実行形式は[開発計画](ROADMAP.md)の対象。

## 責務

| 部品 | 責務 |
|---|---|
| sessions / agent_entry | 新規セッションの研究選択、再開、閲覧専用、分岐 |
| config / budget | 設定、回数、無期限または有限の時間予算、稼働区間の集計 |
| setup / assets / prompts | Agent入口、スキル配置、段階ごとの仕事票と出力契約 |
| store | SQLiteの状態、ジョブ、全試行、履歴、監査イベント |
| engine / providers | 状態遷移、取得・token、並列、実行、CLI接続、復旧 |
| shared_source / quality | 共通コード版、入力固定、環境記録、実行前テスト |
| stopping / confirmation / references | 条件別停止・コスト、確認事前登録、本文固定・引用一致 |
| guards / reporting | 証跡と集計の再照合、報告本文の保存、知見・比較・失敗の出力 |
| evolution | 根拠付きスキル設計、別承認、実装・検証・研究内の有効版 |

## 保存・排他・再開

研究ごとの.rlk/state.sqlite3が正本。セッション選択は.research/sessions.sqlite3で分離する。
SQLiteの取得トランザクションとjob/attempt/tokenで重複取得を防ぐ。外部実行はトランザクション外。
予算を起動前に予約し、不明なrunningを無条件に再実行しない。停止確認後のrecoverとretryで新試行を作る。
研究時間は既定で無期限。有限active_jobsでは研究ジョブの稼働区間をイベントから再計算し、並列を二重加算しない。

成果物保存とDB確定は単一原子操作ではない。完了の正本はcompletion_gate_passedイベント。
exportで確定済み状態から文書を再生成する。ゲートの文書ハッシュは確定時点の値で、累積文書の現在値ではない。
OSサンドボックスや外部サービス副作用の厳密な一度だけの実行は保証しない。

同梱スキルの適用範囲は[SKILLS.md](SKILLS.md)、証跡契約は[EVIDENCE.md](EVIDENCE.md)。
