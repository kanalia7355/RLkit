# 別GitHubプロジェクトへ移す

このフォルダをcloneしてAI Agentで開くと、研究の質問から始められます。利用者のpip操作は不要です。
現在の名前Research Loop Kitは仮称です。GitHub上の公開作業は未実行です。

## ここまで準備済み

- Agentが自動読込するルート指示、SessionStart hook、インストール不要の内部入口
- 再セッション時の研究・方針版・候補選択、条件変更による分岐、結果閲覧モード
- 基本質問と回答依存の深掘り、複数候補、方針提案・修正
- 起動中のAgent方式、4種類のAgent CLI方式、任意CLI方式
- 設定可能な候補数・並列数・seed・時間・回数・サイクル数
- 実装 → 数値実験 → 分析 → レビュー → 報告 → 次サイクル
- 中断時の状態保持、重複取得防止、失敗・再試行・停止
- 共通スキル、ドキュメント、結合テスト、CI定義
- v0.3: 12のlab_ex由来スキル適応、実測照合と成果物保存の完了ゲート、Markdownの知見・問題報告
- v0.4: 報告会用報告書スキル、references同梱、設計承認後のスキル実装・テスト・反映
- 私有の研究データやログを含めない、明示したファイル群からの配布ZIP生成

## 所有者が行うこと

1. **新規GitHubリポジトリを作る。** 所有者・名前・公開/非公開を選ぶ。名前例はresearch-loop-kit。
   この手順では空リポジトリとして作ると扱いやすいです。
2. **ライセンスを決める。** 広く再利用してもらう条件を決め、必要なLICENSEを追加する。
   この成果物ではライセンスを勝手に選んでいません。
3. **ZIPをlab_exの外へ展開する。** 開いたフォルダにREADME.md、AGENTS.md、agent.pyがあることを確認する。
   現版の配布物は `dist/research-loop-kit-0.4.0-source.zip`。移植範囲はSKILL_MIGRATION.mdを参照する。
   親リポジトリの.gitや研究データはコピーしない。
4. **GitHub Desktop等で、このフォルダを新しいリポジトリとして登録して公開する。**
   接続先は手順1で作ったリポジトリ。lab_exのoriginを変更しない。
5. **実際に使うAI Agentをインストール・ログインする。** active方式なら、通常どおりAgentを
   開いて研究フォルダを操作できればよい。外部CLI方式は書き込み権限も設定する。
6. **clone先でAgentを開く。** 質問に答えて研究を始める。返答が入力待ちなら「こんにちは」と一言送る。
   ユーザー自身のテーマで深掘り→提案→採用→実験を一巡して、製品ごとの互換性を確認する。

アカウント作成、ログイン、所有者と公開範囲の選択以外は、このローカル成果物で準備できます。
公開後はCI結果を確認してください。PyPIへの公開は必要ありません。
チームの利用者はclone先をAgentで開いて始められます。Python 3.10以上は内部処理に必要です。

## 配布ZIPの再生成

```console
python tools/export_project.py --output dist/research-loop-kit-source.zip
```

既存のZIPは上書きしません。新しいファイル名を指定してください。
ZIPにはハッシュ一覧EXPORT_MANIFEST.jsonを含め、.research、workspaces、.rlk、.git、認証情報、
ビルド結果、実験ログを含めません。

## 次の育成候補

優先順位は別プロジェクトで利用実績から決めます。

1. 実際のCodex / Claude Code / Gemini CLI / OpenCodeの互換性確認と入口調整
2. 研究分野別の拡張：シミュレーション、機械学習、多群比較、実機の結果取り込み
3. データの版とハッシュ、依存関係固定、コンテナ実行
4. 推測統計と可視化、独立複数Agentレビュー、スキルの独立した行動評価・複数版A/B比較
5. 任意のGitHub連携・通知・常駐運転

受入条件は「その研究分野の一巡が実データで動き、失敗ケースと過大主張を検出できること」。
スキルを増やすだけで実行契約や出力の検証がつながっていない状態を完成扱いにしません。
