# clone後の起動仕様

## 読み込み経路

| Agent | 自動読み込み | 状態に応じた起動時表示 |
|---|---|---|
| Codex | ルートのAGENTS.md | 最初の応答でRESEARCH_START.mdに従い、入口を開く |
| Claude Code | CLAUDE.md → AGENTS.md | SessionStart hookで挨拶と文脈を注入。最初の応答で入口を開く |
| Gemini CLI | GEMINI.md → AGENTS.md | SessionStart hookで挨拶と文脈を注入。最初の応答で入口を開く |
| OpenCode | AGENTS.md | 最初の応答で入口を開く |
| その他 | 指示ファイルの読み込み機能があればAGENTS.mdを指定 | 共通手順を読む方式で対応 |

CodexのAGENTS.mdは起動時に読み込まれます。[公式仕様](https://learn.chatgpt.com/docs/agent-configuration/agents-md)
Claude CodeのSessionStartは起動・再開などで文脈を追加できますが、対話モードで新しい会話ターンを
作るものではありません。[公式仕様](https://code.claude.com/docs/en/hooks#sessionstart)
Gemini CLIはSessionStartのsystemMessageとadditionalContextを使います。[公式仕様](https://geminicli.com/docs/hooks/reference/#sessionstart)
OpenCodeはプロジェクトのAGENTS.mdを読み込みます。[公式仕様](https://opencode.ai/docs/rules/)

これらは2026-09-11に確認した仕様です。自動読み込みと、無入力でのモデルの返答開始は別の機能です。
返答を待機する製品では最初の一言が必要です。Pythonコマンドの入力をユーザーに求める設計ではありません。

## hookとフォールバック

Claude Codeはexec形式のSessionStart設定を使い、Gemini CLIは同製品のcommand形式を使います。
hookはpythonコマンドが使える環境を想定します。python3のみの環境ではAgentがプロジェクト設定を
その環境に合わせて調整できます。hookが無効・未承認・実行不可でも、指示ファイルからの開始は可能です。
hook自体は読み取り専用で、研究の初期化・予算変更・実験起動を行いません。
Agentの信頼確認・hook承認・組織ポリシーをこのパッケージで解除することはありません。

## セッションの扱い

- 新規起動・再開・clear・fork: 新しい選択用IDを発行し、前の選択を自動で再利用しない。
- セットアップ途中: 未回答の質問を返す。回答済みの内容を聞き直さない。
- 方針あり: 方針版・候補・実験結果・失敗・残り予算を返す。
- 会話圧縮: 選択を維持し、メニューを何度も出さない。
- 具体的なjobを処理する実働Agent: 起動質問を開始しない。
- ツール本体を開発する依頼: 研究セットアップを開始しない。

セッションごとの選択は他のセッションの選択を書き換えません。同じ研究へ複数セッションがアクセスしても、
仕事の排他は既存のジョブ機構が維持します。メニュー表示後に研究状態が変われば、古い表示からの選択を拒否します。
既に動いているプロセスは新しいセッションを開いただけでは停止しません。

## 方針・候補の選び直し

方針の保存版はplanジョブごとに保持されます。版を指定して修正する場合、その方針を作った時点の
候補を参照し、別サイクルの同名IDと混同しません。候補の選び直しでは利用者が選んだ候補だけから
計画を作り、初回と同じく採用前に具体案を示します。

条件変更・候補選択・方針修正は、新しい研究フォルダに分岐します。
元の研究への参照、回答、方針、過去の結果を引き継ぎますが、旧実験の実測値を新研究の実測として扱いません。
計画の承認・ジョブ・試行回数・開始時刻をコピーしません。

## 検証の範囲

起動hookのJSON、未インストールのcloneでの入口、再セッションの選択ゲート、方針版の選択、
候補を選び直して実験が完了する経路を自動試験します。
各製品の対話UIが実際に自動読み込みして質問するところは、ログイン済み環境での確認が残っています。
