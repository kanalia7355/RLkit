# RLkitの目的と方針

## 目的

研究・実験の大方針とデータを受け取り、AIエージェントが計画、実験、検証、分析、図表作成、報告、次の提案を継続するシステムを目指す。
元の実験自動化システムはGA・画像処理の研究を対象とし、次の実験提案まで自動化していた。
RLkitはその目的と研究方針／実験実行の二段構造を継承し、研究固有の前提を汎用的な設定・契約・テンプレートへ分離する。

## 継承する構造

- 方針と制約に基づいて複数の実験候補を考え、具体的な計画へ落とす。
- 実測・証跡に基づいて実験を検証し、失敗も分析と報告へ含める。
- 結果と限界から次の探索を提案し、承認された範囲で次のサイクルへ進む。
- 履歴・試行・コード・データ版を保持して中断・再開・復旧できるようにする。
- 再利用できる研究コードと知見を蓄積する。

GAの世代・個体、画像処理指標、特定データセット、固定seed数、placebo条件、専用の検定式は全研究へ強制しない。
画像処理・GAの知見は分野別テンプレートとして保存し、元の用途でも使えることを一般化の受入基準にする。
現時点のリポジトリには元システム全体はなく、既存の移植対応記録を基準にしている。原実装・研究固有の条件を確認するまでは完全再現を称しない。

## 初回設定と自動運転

初回は目的、データの意味・利用条件、評価基準、固定条件、変更可能な範囲、資源、停止条件、必要成果物を聞く。
回答済みの情報を何度も聞かず、不足する点だけ確認する。利用者に内部コマンドや設定JSONの作成を求めない。

承認した大方針の範囲では、Agentが具体的な計画・実装・検証・分析・報告・次の提案を進める。
現行のboundedは初回承認後の計画を自動採用する設定、review_each_cycleは毎サイクル確認する設定。
研究目的・データ利用条件・変更禁止条件・予算・外部サービス利用が変わる場合は自動で承認範囲を広げない。
現行の境界判定はAgentの仕事票とレビューにも依存し、自然言語の方針逸脱をランタイムだけで自動検出するものではない。
未解決事項がある計画は両モードで停止する。スキルの実装・有効化は別途設計承認が必要。

## 無期限の中断・再開

新規研究の研究全体の時間予算は既定で無期限（max_wall_seconds=null）。経過日数だけで再開を拒否しない。
実験回数・サイクル数・Agent呼出し数、個別作業のタイムアウト、条件別の停止方針は独立して管理する。
無期限でも回数上限や完了状態を解除しない。完了済み研究は確認実験または分岐を選ぶ。

必要なら有限の時間予算を設定できる。新規設定のactive_jobsは、最初の方針承認後に研究ジョブが取得されてから完了・失敗するまでの区間の合計を計測する。
並列区間は二重計上しない。pending、質問・方針承認待ち、稼働ジョブのない中断・一時停止は計上しない。
pauseしても実行中プロセスは直ちに停止しないため、そのジョブが完了するまで計上する。
activeの取得済み仕事にはAgentの応答待ちも含む。稼働有無不明のrunningを自動で消さず、プロセス停止確認後にrecoverする。
スキル作業は別の呼出し予算で管理し、研究稼働時間から除外する。
再起動を跨ぐ記録はOS時計を使う。完了区間と状態更新時までに計上した時間は巻戻りでも減らさない。
稼働中の未保存区間や時計の大幅変更では正確な実時間を保証しない。個別プロセスのタイムアウトは別途維持する。

旧版で保存した有限上限はelapsed（初回承認からの経過時間）として維持する。旧研究の期限を勝手に解除しない。
深掘り前ならconfigureで変更、固定済み研究は設定変更の分岐で無期限／active_jobsを選ぶ。

## 成果物と判断の信頼範囲

実行記録の整合性、閾値再現、事前登録した検定の基準達成、研究上の解釈・一般化を区別する。
実測・図表・報告を捏造せず、未対応・未検証を明記する。同じAgentの実装とレビューを独立査読と称しない。
既定の成果物は研究内のMarkdownと機械用JSON。外部への自動投稿はしない。
図表生成・自動添付は目標であり、現行ランタイムの必須成果物にはまだ含まれていない。

## 現行の対応範囲

現行の実行口はPythonの計算実験・データ分析、同一seedの対照／介入の数値比較。
この形式は最初の実行アダプタとして扱い、PJ全体を定義するものにはしない。
単独評価、多条件比較、非乱数実験、外部シミュレータ、実機は今後の拡張。未対応の課題を無理にseed比較へ変換しない。
入力固定は明示登録した100MiB以内のファイル。任意の投入データを自動理解・取得する仕組みは未実装。

具体的な優先順と受入条件は[開発計画](ROADMAP.md)、元システムとの対応は[アーキテクチャ](ARCHITECTURE.md)と[移植対応](SKILL_MIGRATION.md)を参照する。
