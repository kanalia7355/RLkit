# Active方式の受け入れ検証

実施日: 2026-09-30 / Python 3.12 / Linux

この開発セッションのAgentが数値積分とCSV回帰の計画・実装・検証回答を作成し、backend=activeで作業票を取得してsubmitした。
深掘り、候補、方針、承認、実装、別作業の実行前レビュー、実験、結果レビュー、未使用seedでの確認までを通した。

各題材で7件のAgent回答を提出し、探索3seed・確認3seedを実行した。検証seedの実行は別に実行前レビューへ記録される。
手動介入0は、所定のAgent回答・方針承認・確認依頼に加えた状態修復や再試行が0件という意味。人やAgentの介在なしという意味ではない。

| 題材 | 段階 | 対照平均 | 介入平均 | n | 結論状態 |
|---|---|---:|---:|---:|---|
| 指数関数の数値積分 | exploration | 0.0352231014 | 0.000227226977 | 3 | exploratory |
| 指数関数の数値積分 | confirmation | 0.0323371746 | 0.000209127293 | 3 | confirmed |
| CSVの線形回帰 | exploration | 6.60995987 | 0.000611109104 | 3 | exploratory |
| CSVの線形回帰 | confirmation | 5.43926638 | 0.000465578248 | 3 | confirmed |

数値積分はexp(alpha*x)の左端則と台形則を32区間で比較し、解析式から絶対誤差を計算した。
CSVは40行の合成データを30行訓練・10行評価に分割し、訓練平均の定数予測と切片付きOLSの評価MSEを比較した。
探索seedは11/22/33、確認seedは101/102/103。いずれもmin_effect=0.001。統計的有意差の検定は未実施。

## 詰まり・介入・実装誤り

- 2題材とも予定外の停止、復旧のための介入、実装誤りの検出は0件。
- 閾値到達は探索時にexploratory、固定条件の確認後にconfirmedとして保存された。
- 回帰テストでは、停止フックを外した実装が実行前検証で失敗し、本実験のrunsが0のままであることを確認した。
- 開発中は、同じ回答オブジェクトの再提出で予約モジュールを拒否する不具合を検出し、同一本文の再提出を受理するよう修正した。

## 再実行と検証範囲

`python tools/active_acceptance.py --output /tmp/rlk-acceptance`で今回作成した作業回答を再実行できる。
出力先に作業票、回答、事前登録、入力コピー、コード、テストログ、seed別測定値、停止記録、報告書、acceptance-summary.jsonを残す。
スクリプトは固定回答の再実行であり、それ自体はAgentの推論を行わない。
実装とレビューは同じAgentが行った。認証済み外部CLIでの起動・権限・ツール実行、独立査読、未知課題での自律的研究能力は未検証。
比較は既知の合成例に限定される。新規研究成果や実データへの一般化を示す結果ではない。
