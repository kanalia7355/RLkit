# Research Loop Kit

cloneしたフォルダでAI Agentを開き、質問に答えるところから始める研究用ツールです。仮称・バージョン0.4.0です。

CodexやClaude Codeなど、**今開いているAgentをそのまま進行役にできます**。特定の研究データ、モデル名、GitHubアカウントには依存しません。

報告・不具合・改善候補は**ローカルMarkdownが既定**です。GitHub Issueへの投稿機能はありません。
共通4スキル、lab_ex由来の12適応スキル、研究報告書作成と承認付きスキル育成の2スキルを同梱しています（計18）。
元の全スキル・全スクリプトの移植ではありません。[移植対応表](docs/SKILL_MIGRATION.md)に実装・助言・未対応を区別しています。

報告会には、背景・方法・実測表・考察・次の方針・相談事項・出典を含む `MEETING_REPORT-NNN.md` を自動生成します。weekly系のスキルは含めません。
スキル候補は根拠付きで設計書へまとめ、ユーザーが設計を承認すると実装・テスト・研究への反映まで進みます。
設計にはreferencesの出典・用途・同梱本文、必要資源、適用条件、正常/異常系の検証を必須としています。
反映済みスキルは同じ研究の後続作業に適用されます。詳細は[スキル育成](docs/SKILL_EVOLUTION.md)。

## 使い始める

1. このリポジトリをcloneするか、配布ZIPを展開する。
2. **そのフォルダでCodex、Claude Code、Gemini CLI、OpenCode等を開く。**
3. Agentからの研究テーマ・関心の質問に答える。

ユーザーによるPythonコマンドの入力やpipインストールは不要です。状態保存と実験に使うPython 3.10以上はAgentが確認し、同梱の入口を内部で扱います。環境にPythonがなければ準備が必要ですが、最初の質問は会話から始められます。

ルートのAGENTS.md / CLAUDE.md / GEMINI.mdが自動読み込みの入口です。Claude CodeとGemini CLIにはSessionStart hookも同梱しています。Agentのフォルダ信頼・hook確認が表示される場合は、利用者が内容を確認して有効にしてください。

Agent自体が入力まで返答を生成しない場合は、「こんにちは」など一言だけ送ってください。その最初の返答から質問が始まります。**全製品で、無入力のまま自発的に話し始めることは保証しません。** 詳細は [起動仕様](docs/STARTUP.md)。

## 初回と、次に開いたとき

方針が未設定なら、研究の種類、関心の理由、先行研究、データ、比較方法、資源、変更禁止条件、欲しい成果物を聞き取ります。回答に応じて追加質問を作り、複数候補から実験方針を提案します。途中で閉じても、次は未回答の質問から続けられます。

方針がある場合は、前回の方針・候補・進捗・結果・残り予算を示して、今回の進め方を尋ねます。

- 同じ方針・条件で続ける
- 保存済み候補から選び直す（複数選択可）
- 前回または過去版の方針を修正する
- 関心・データを引き継ぎ、設定を変えて分岐する
- 別テーマを始める
- 方針・結果だけ見る

候補数や並列数、seed、予算などの詳細も会話で選べます。方針修正・条件変更では新しい研究へ分岐し、元の結果を保持します。「そのまま続行」は前回の予算をリセットしません。結果を見るモードでは、内部入口が実験・状態変更を拒否します。

具体的な方針で進めることが決まると、実装→実験→分析→レビュー→報告→次の候補へ進みます。

## 調整できること

| 設定 | 意味 | 既定値 |
|---|---|---:|
| candidate_count | 毎サイクルに考える候補の総数 | 6 |
| proposal_workers | 異なる観点で候補を考える作業数 | 3 |
| experiments_per_cycle | 候補から採用する実験数 | 2 |
| max_parallel_agents | AI作業の同時処理上限 | 2 |
| max_parallel_experiments | 実験プロセスの同時実行上限 | 1 |
| deep_questions | 基本回答を受けた追加質問数 | 4 |
| seeds | 両条件に使う乱数seed | 11,22,33,44,55 |
| max_cycles | 研究サイクル数の上限 | 1 |
| max_agent_calls | 深掘り・提案・実装・レビューの作業試行数上限 | 40 |
| max_runs | seed別プロセス起動数の上限（再試行も消費） | 30 |
| max_attempts | 1ジョブの最大試行回数 | 2 |
| agent_timeout_seconds | 外部Agent CLIの1作業の時間上限 | 900 |
| run_timeout_seconds | 1seedの実行時間上限 | 300 |
| max_wall_seconds | 最初の方針承認からの経過時間上限 | 7200 |
| autonomy | 方針確認の頻度 | review_each_cycle |

設定はAgentとの会話で変更できます。[examples/settings.json](examples/settings.json)はAgent・開発者向けの設定例です。

`proposal_workers` は候補生成ジョブ数です。実際のAI並列数は `max_parallel_agents` とAgent側の機能に制約されます。active方式では1つのAgentが順番に処理しても動きます。実験はランタイムが指定数まで並列化し、各実験内のseedは順番に実行します。

`review_each_cycle` は毎サイクルの方針提示で確認します。`bounded` は最初に承認した設定・研究プロファイルの範囲で次サイクルも進めます。どちらも未解決事項を含む計画は止めます。設定は深掘り開始時に固定します。

回数上限はAPIトークン数や金額の上限ではありません。CLIのログイン先・モデルの料金や使用量制限は各サービス側で管理します。active方式の経過時間上限は新規作業取得時に確認し、Agentの思考や実行中のツールを強制終了するものではありません。

## 対応Agent

| 選択肢 | 使い方 | この版での検証 |
|---|---|---|
| active（推奨） | 現在のAgentが共通作業票を読み、JSONで返す | ファイルの受け渡しから実行まで結合検証 |
| codex | Codex CLIへ作業票を渡す | 起動引数を実装。認証付き実運用は未検証 |
| claude | Claude Codeの非対話モード | 同上 |
| gemini | Gemini CLIの非対話モード | 同上 |
| opencode | OpenCodeのrunコマンド | 同上 |
| custom | 任意の実行ファイルと引数の配列 | 実プロセスによる契約試験済み |
| demo | 決定論的応答＋実際の数値計算 | 2サイクルの動作実証済み |

外部CLI方式は、各CLIのインストール・ログイン・作業フォルダへの読み書き権限設定が必要です。権限を全解除するフラグは自動追加しません。セットアップは現在のAgentで進め、外部処理したい段階で `rlk run ../my-research` を使えます。activeと外部CLIの混在は [docs/AGENTS.md](docs/AGENTS.md) を参照してください。

## 何が保存されるか

clone先の `.research/projects/` に研究ごとのフォルダを作ります。その中の `.rlk/state.sqlite3` が状態・仕事票・全試行・監査イベントの正本です。セッションごとの選択は `.research/sessions.sqlite3` に保存します。仕事票ごとに別フォルダを使い、実験はさらにseed別にログと測定値を保存します。事前登録には計画ハッシュ、コードハッシュ、seed、PythonとOSの情報を記録します。

研究ごとの `reports/` には方針、サイクル報告、知見、現在状態を出力します。Agentに「結果を見せて」と伝えてください。バックアップ時は **Gitで無視される `.research/` 全体**を保存します。第三者に渡すのはツール本体を基本とし、研究データを含めるかは利用条件に従って判断します。

## この版の対象と限界

初期版の実験実行口は **Pythonの計算実験・データ分析で、同じseedの対照条件と介入条件の数値を比較する形式**です。主指標は任意に定義できます。実機操作、参加者を伴う研究、多群の推測統計、分散GPUジョブなどを自動で取り扱う実装はまだありません。セットアップでそうした条件を確認し、準備不足なら方針の未解決事項として扱います。

平均・標準偏差・事前に決めた改善幅は計算しますが、統計的有意差は自動判定しません。Pythonコードは利用者のOS権限で走り、作業フォルダの分離はセキュリティサンドボックスではありません。信頼できるAgent・コードで使い、環境隔離が必要な研究ではコンテナ等を別途用意してください。

active方式はAgentセッションが動いている間に進行し、常駐サービスは作りません。外部CLI方式のrunは対話・承認・失敗・予算上限・完了まで処理します。深掘りへの人間の回答は自動化しません。
